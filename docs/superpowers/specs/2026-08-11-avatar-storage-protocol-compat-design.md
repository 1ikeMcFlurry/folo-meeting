# 头像存储兼容与双配置协议同步设计

## 目标

修复动态头像目录上线后的两个启动警告，同时保证已有设备升级时不破坏音频数据，并让小程序与手持终端各自使用的配置协议与固件实现保持一致。

## 分区兼容

`audio` 分区保持历史地址 `0x37a000` 和大小 `0x80000`，以便已有 SPIFFS 文件系统在升级后继续挂载。扩展后的 1MB `imgava` 分区放在 `audio` 后方，地址为 `0x3fa000`。构建、普通 `idf.py flash`、发布合并固件和文档均从分区表读取或使用这一布局，不再通过移动 `audio` 为头像扩容。

自动化测试固定检查 `audio` 的兼容地址、`imgava` 的大小及两者不重叠。完整固件构建必须生成并纳入新的 `imgava.bin`。

## 头像名称迁移

档案历史默认值仍可能是 `default`，而动态目录不要求存在该名称。启动时若保存名称不存在，设备选择头像目录按名称排序后的第一项，保存新名称并继续显示。该情况属于预期兼容迁移，记为 INFO；资源包初始化失败、目录为空或迁移落盘失败仍记为错误或警告。

## 小程序连接配置协议

`doc/ble-protocol-spec.md` 是小程序通过 BLE 连接修改设备信息的规范。文档明确 JSON 配置字段 `nickname`、`avatar_name`、`token`、`token_max`、`time` 的类型、范围、持久化行为、状态返回和示例。

头像只传 `avatar_name`，名称必须匹配固件随包交付的 `avatar_catalog.json`；本通道不接收头像 PNG。未知头像不得覆盖当前头像。

## 手持终端广播配置协议

`doc/ble-broadcast-protocol-for-gateway.md` 同时记录两类签名广播：

- v1 token 操作广播继续用于加分、扣分、失败提示和静默余额同步。
- v2 档案广播 `0x23` 用于修改 token 绝对值、token 上限、时间、昵称和头像名称。

v2 文档给出完整 26 字节厂商数据布局、字段编号、3 字节数据分片、事务号、HMAC 输入、分片重组、3 秒超时、去重和重复发送规则。头像字段只承载资源名称，并要求发送方使用对应固件发布包中的 `avatar_catalog.json` 校验名称。
