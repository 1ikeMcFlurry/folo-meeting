# BLE 全屏截图设计

## 目标

上位机通过现有 BLE 连接请求截图。设备捕获命令到达时正在显示的完整
240×320 屏幕，包括主页、游戏、全屏图片和自检页面，将画面传回
`tools/ble_card_client.py`。上位机校验数据后弹出“另存为”窗口，并将截图保存为
JPG。

## 范围

本功能包含设备端按需截图、BLE 可靠分片回传、上位机接收与进度显示、RGB565
转换、完整性校验和 JPG 另存为。

设备不保存截图，也不编码 JPEG。截图期间冻结当前画面，预计持续 15–40 秒。
本次不增加后台自动截图、固定目录自动保存、截图历史或其他传输方式。

## 约束与方案选择

屏幕为 ST7789P3，分辨率 240×320、像素格式 RGB565。ESP32-C3 无 PSRAM，常驻
完整影子帧缓冲需要 153,600 字节，不符合当前内存条件。LCD SPI 未连接 MISO，
不能从面板显存读回。

采用按需强制 LVGL 全屏重绘并截获刷新分块的方案。当前所有目标界面均由 LVGL
绘制，因此可以覆盖主页、游戏、全屏图片和自检页面。显示继续正常写入 LCD，
同时将相同的 RGB565 分块交给截图传输状态机。设备只保留当前刷新分块及一个
BLE 包级暂存区，不分配完整屏幕缓冲。

## 架构

### 截图控制服务

截图业务使用新的应用消息类型 `0x06`。它负责处理 `START`、`ACK`、`FINISH` 和
`CANCEL` 操作，维护唯一的活动截图 ID、期望确认序号、重试次数和超时。

现有状态 Notify 特征 `54524145-4341-5244-0000-000000000011` 继续返回业务状态。
新增截图数据 Notify 特征 `54524145-4341-5244-0000-000000000014`，只承载截图元
数据、像素分块和结束包。拆分状态和大数据可保持旧客户端兼容，并避免把现有固定
2 字节状态通知改成变长格式。

### 显示捕获服务

显示层增加一次性全屏捕获接口。开始捕获时，它暂停界面动画和按键输入，将当前
活动屏幕全量标记为需要重绘，并截获此次重绘产生的全部刷新区域。每个刷新区域仍
写入 LCD，同时以坐标和区域内偏移交给截图控制服务。

截图控制服务在上位机确认当前数据包之前不允许复用其对应的刷新数据。实现需要把
等待逻辑放在专用传输任务中，并通过队列/信号量协调 LVGL 任务，不能在 NimBLE host
回调中执行阻塞式绘制或等待。

捕获成功、取消、超时、断连或失败时，统一执行幂等清理：解除输入和动画冻结、清空
活动截图状态并释放暂存资源。

### 上位机

`tools/ble_card_client.py` 增加截图页面或截图区域，包括“截图并保存”按钮、字节
进度、状态文本和“取消”按钮。只有 BLE 已连接且截图数据特征订阅成功时才能开始。

后台 Bleak 事件循环负责协议收发和重组，不直接调用 Tk。完整且校验通过的 RGB565
画面通过现有线程安全事件队列交给 GUI 线程。GUI 线程弹出“另存为”窗口，默认文件
名为 `trae-card-YYYYMMDD-HHMMSS.jpg`，使用 Pillow 以质量 90 保存。

## 协议与数据流

### 控制命令

控制命令仍使用现有应用层帧 `[ver][type][len_le16][payload]`，其中 `type=0x06`。
payload 第一个字节为操作码：

| 操作 | 操作码 | 后续字段 |
|---|---:|---|
| `START` | `0x01` | 无 |
| `ACK` | `0x02` | `capture_id:u16le, seq:u16le` |
| `FINISH` | `0x03` | `capture_id:u16le` |
| `CANCEL` | `0x04` | `capture_id:u16le` |

设备每次接受 `START` 时分配非零 `capture_id`。过期 ID、非期望序号或非法时序返回
时序错误，不推进状态机。

### 截图数据包

截图数据特征的每条通知以 `kind:u8` 开头：

| kind | 名称 | 内容 |
|---:|---|---|
| `0x01` | META | `capture_id:u16le, seq:u16le, width:u16le, height:u16le, format:u8, total_len:u32le` |
| `0x02` | DATA | `capture_id:u16le, seq:u16le, x:u16le, y:u16le, w:u16le, h:u16le, region_offset:u32le, bytes...` |
| `0x03` | END | `capture_id:u16le, seq:u16le, packet_count:u16le, total_len:u32le, crc32:u32le` |

`format=0x01` 表示小端 RGB565。多字节整数均为小端。DATA 像素载荷按当前 ATT MTU
动态取最大值。区域坐标与 `region_offset` 使上位机不依赖 LVGL 的刷新顺序，可将任意
合法区域放到最终画布中的确定位置。

META、每个 DATA 和 END 都占用一个连续序号，并要求上位机返回相同截图 ID 和序号的
ACK。设备收到正确 ACK 后才发送下一包。设备不依赖 Notify 自身的可靠性。

CRC32 按最终画布从上到下、每行从左到右的 153,600 字节小端 RGB565 数据计算，而
不是按通知到达顺序计算。

### 完整时序

1. 上位机订阅状态特征和截图数据特征，然后发送 `START`。
2. 设备检查资源互斥和订阅状态，接受后返回截图业务 ACK，并冻结、重绘当前画面。
3. 设备发送 META；上位机校验参数并 ACK。
4. 设备逐个发送 DATA；上位机按坐标写入画布、更新覆盖信息和进度，再逐包 ACK。
5. 设备发送 END；上位机检查序号、覆盖范围、总长度和 CRC32，再 ACK。
6. 校验成功后，上位机把 RGB565 转为 RGB888，并在 GUI 线程弹出“另存为”。
7. END 被正确 ACK 后，设备已经完成传输，立即解除冻结并返回 DONE，不等待用户操作
   文件对话框。
8. 保存成功发送 `FINISH` 作为结果确认；用户取消保存发送 `CANCEL`。这两个操作在
   传输完成后只结束该截图 ID 的结果跟踪，不会再次改变屏幕状态。主动取消仍可在传输
   期间随时发送 `CANCEL`。

截图期间，截图按钮禁用而取消按钮启用。图片上传及其他占用大量 BLE 或显示资源的
操作与截图互斥。普通低流量状态通知可以继续工作，但不能启动第二个截图。

## 颜色与方向

截获的是 LVGL 的逻辑 RGB565 像素，不能把 LCD SPI 的字节交换再次应用到截图数据。
上位机按小端 RGB565 解码：5 位红、6 位绿、5 位蓝分别扩展到 8 位。输出必须保持
240×320 竖屏方向，不再镜像或旋转。

屏幕圆角由 LVGL 活动屏的裁剪及底层黑色背景共同产生。强制全屏重绘必须包含底层
黑色区域，确保截图四角与实际显示一致。

## 错误处理

- 每个需要 ACK 的数据包等待 3 秒，超时最多重发 3 次；仍未确认则终止并报告超时。
- 断连、`CANCEL`、缓冲申请失败或重绘失败都立即执行幂等清理，不能留下冻结界面。
- 截图进行中再次 `START`，或与图片上传等互斥操作冲突时，返回设备忙。
- 无截图数据特征订阅时拒绝 `START`，避免设备进入无法完成的传输状态。
- 上位机遇到未知截图 ID、非法坐标、越界区域、错误区域偏移或不符合预期的序号时，
  立即取消，不写出文件。
- 只有全部 240×320 像素恰好被覆盖且 CRC32 正确时才允许进入保存步骤。
- END 被确认后立即解除冻结，避免用户长时间停留在文件对话框时冻结设备。设备最多
  保留截图 ID 的轻量结果跟踪状态 5 分钟，届时自动清除，不占用显示或传输资源。
- 文件对话框取消不创建文件，并向设备发送 `CANCEL`。磁盘写入失败显示错误并发送
  `CANCEL`。
- 所有终结路径恢复按钮状态；断连路径还应丢弃内存中的未完成画布。

## 状态码

截图沿用通用的 ACK、DONE、帧错误、超时、时序错误、内存/存储类失败、设备忙等
状态。新增截图特有错误时优先复用现有语义；只有无法准确表达时才增加状态码，并在
`hal_config.h`、协议文档和上位机状态文本中同步定义。

## 测试

### 设备端单元与 Host 测试

- 控制包编解码：合法 START/ACK/FINISH/CANCEL、错误长度、过期 ID 和错误序号。
- 状态机：正常完成、重复 START、取消、断连、每个阶段超时及三次重试上限。
- 分块：不同 MTU 下的载荷边界、区域跨多个 BLE 包、乱序刷新区域和最后一个短包。
- 模拟显示刷新：多个区域最终恰好覆盖 240×320；缺块、重叠冲突、越界均不成功。
- CRC32：已知向量以及按最终画布顺序计算，不受刷新区域顺序影响。
- 资源清理：所有成功和失败路径均解除冻结并复位状态。

### 上位机测试

- META/DATA/END 解析和非法包拒绝。
- RGB565 到 RGB888 的红、绿、蓝、黑、白已知颜色向量。
- 正常重组、乱序区域重组、缺块、重复包、序号错误和 CRC 错误。
- 正常保存、取消保存、磁盘错误、传输中取消、断连和重复点击。
- GUI 更新只在 Tk 主线程执行，截图期间按钮和进度状态正确恢复。

### 实机验收

分别截取主页、游戏、全屏 JPEG 和自检纯色页面。逐张比较颜色、方向、圆角、文字与
设备实际显示；确认 JPG 为 240×320。验证 15–40 秒传输期间画面保持稳定，成功、
取消、超时及断连后按键和动画均正常恢复。再执行一次图片上传，确认互斥状态不会
破坏已有图片传输协议。

## 文档兼容性

实现时将 `doc/ble-protocol-spec.md` 升级协议版本，补充 `0x06`、`…0014`、包格式、
时序、超时和兼容性说明。旧上位机不订阅 `…0014`、也不发送 `0x06`，现有配置、
图片、乐谱、音频和只读特征行为保持不变。
