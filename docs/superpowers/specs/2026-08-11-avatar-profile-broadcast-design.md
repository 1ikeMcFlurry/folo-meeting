# 本地头像资源与广播档案更新设计

## 目标

设备不再通过 BLE 上传头像图片。头像改为生产阶段预烧录到 `imgava` 分区的本地 PNG 资源，BLE 和广播只传头像名称，由设备按名称选择并显示。现有 token 广播扩展为可安全修改昵称、头像名称、Token 余额、Token 上限和系统时间，同时保持旧 v1 token 广播兼容。

## 头像资源

### 资源目录与命名

- 源文件位于 `assets/avatars/`。
- PNG 文件名去掉 `.png` 后即为协议中的 `avatar_name`。
- 名称只允许小写 ASCII 字母、数字、下划线和连字符，最长 15 字节。
- 资源包必须至少包含 10 张头像，且必须包含 `default.png`。
- 首批名称为：`default`、`neon_cat`、`cyber_fox`、`holo_bear`、`mint_robot`、`amber_bot`、`violet_owl`、`aqua_panda`、`red_rabbit`、`blue_wolf`。

### 图片规范

- 统一为 `96×156px`、RGBA 8-bit、非交错透明 PNG。
- 头像内容可按发行需要动态增减；目录非空即可，1MB 分区按规定规格至少能容纳 10 张，名称和 PNG 属性由打包器校验。
- 不含文字、Logo、投影或背景。
- `default` 为绿色机器人，其余为不同配色的人物或机器人。
- 构建工具必须拒绝设备 PNG 解码器不支持的位深、颜色类型或交错格式。

### `imgava` 资源包格式

`imgava` 使用 1MB 生产预烧录分区，由单张运行时图片槽改为只读多头像资源包。构建工具动态扫描 `assets/avatars/*.png`，生成固定头、名称索引、偏移、长度、CRC32、顺序拼接的 PNG 数据和 `avatar_catalog.json`。

固件 mmap `imgava` 分区并按名称零拷贝定位 PNG，避免为压缩文件额外申请 RAM。资源包生成时校验目录非空、名称、重复项、PNG 属性、索引边界和总容量；任一条件不满足则构建失败。已保存名称不存在时回退到按名称排序后的第一张头像，不要求文件名固定为 `default`。

`idf.py flash` 必须自动烧录头像资源包。`scripts/release.py` 生成的合并固件也必须包含 `imgava` 分区镜像，不能沿用当前忽略运行时数据分区的行为。

## 设备头像显示

- `profile_data_t` 新增 `avatar_name[16]`，出厂默认值为 `default`。
- NVS 档案版本升级，并从当前旧版本迁移已有昵称、Token、游戏积分等字段；旧档案的头像名称补为 `default`。
- 启动时读取已保存的名称，从头像资源包定位 PNG，复用现有 PNG 到 `imgframe` 的流式解码和主页 `lv_image` 显示链路。
- BLE 或广播修改头像时，先验证名称存在且索引、长度和 CRC 正确；成功后才保存名称并刷新显示。
- 未知、损坏或未打包的名称不修改档案，不清除当前头像。BLE 返回明确错误；广播只写限频日志，不响提示音。
- 全屏图片仍会覆盖共享的 `imgframe` 解码缓冲；退出全屏后按当前 `avatar_name` 重新解码恢复头像。

## BLE 配置变化

- JSON 新增推荐字段 `nickname` 和字段 `avatar_name`。
- 旧 `name` 字段继续作为昵称别名，保持上位机和已有调用兼容。
- 上位机头像控制改为名称选择/发送，不再选择或上传头像文件。
- 固件删除头像图片上传入口。图片数据上传只保留 `fullscreen` 模式。
- 全屏图片上传、设备截图回传及其他 BLE 配置保持不变。

## 广播协议

### v1 兼容

现有 26 字节 v1 token 加分、扣分、业务失败、余额同步和宠物开关广播保持原格式、验签、去重、提示音和奖励动画行为。

### v2 档案字段更新

v2 仍使用恰好 26 字节的厂商数据，适配当前 Legacy BLE 广播容量：

| 字节 | 内容 |
|---|---|
| `0..1` | ASCII `HB` |
| `2` | 版本/类型 `0x23` |
| `3` | 字段 ID |
| `4..9` | 目标设备 MAC，6 字节 |
| `10..11` | 事务 ID，uint16 little-endian |
| `12` | 分片序号，从 0 开始 |
| `13` | 分片总数 |
| `14` | 字段总长度 |
| `15..17` | 本片数据，最多 3 字节，末片不足补 0 |
| `18..25` | 对 `0..17` 计算的 HMAC-SHA256 前 8 字节 |

字段定义：

| ID | 字段 | 编码与限制 |
|---|---|---|
| `0x01` | `token` | uint32 little-endian，绝对余额 |
| `0x02` | `token_max` | uint32 little-endian，最小 1 |
| `0x03` | `time` | uint32 little-endian Unix epoch 秒 |
| `0x04` | `nickname` | UTF-8，最长 47 字节，安全截断/校验字符边界 |
| `0x05` | `avatar_name` | ASCII，最长 15 字节，使用资源名称规则 |

每次事务只修改一个字段。设备按目标 MAC、字段 ID 和事务 ID 重组；每片独立验签。允许乱序和重复分片，3 秒未收齐则丢弃。只有全部分片到齐、总长度一致且字段校验通过后才原子应用。已完成事务进入有限去重窗口，防止网关重发造成重复副作用。

## 应用行为

- v1 `ADD`/`SUB` 保留提示音和奖励动画；v1 `SYNC` 保持静默。
- v2 `token`、`token_max`、`nickname`、`avatar_name` 和 `time` 全部静默更新。
- `nickname`、`avatar_name`、`token` 和 `token_max` 成功后写入 NVS；`time` 仅调用系统校时，不写 NVS。
- 任一 v2 事务失败只影响该事务，不改变已有档案或其他字段。
- 截图占用 LVGL 时继续遵守现有 capture gate，不能在 NimBLE host 回调中阻塞等待 LVGL；档案先保存，UI 在安全路径刷新或后续同步。

## 验证

### 自动化

- 资源打包：合法非空包、动态增删、非法/重复名称、不支持 PNG、CRC、偏移越界和 1MB 超限。
- 资源读取：按名称命中、未知名称、损坏索引、CRC 错误和 mmap 生命周期。
- v2 广播：验签失败、错误目标、错误字段、错误长度、乱序、重复片、超时、事务去重、UTF-8 边界和收齐后原子生效。
- 档案：默认头像名称、旧版本迁移和新版本序列化。
- BLE JSON：`nickname`、兼容 `name`、`avatar_name`、未知头像错误及头像上传路径移除。
- 上位机：仅发送头像名称；全屏上传和设备截图保持可用。
- ESP-IDF 5.5.3 构建、固件大小检查、头像分区镜像生成及发布合并固件内容检查。

### 真机

- 10 张头像均可按名称显示，透明背景、方向和颜色正确。
- BLE 与 v2 广播可修改昵称、头像、Token、Token 上限和时间。
- v1 token 广播仍可加减、同步和控制宠物。
- 重启后昵称、头像和 Token 数据保持。
- 未知头像不会清空当前显示。
- 全屏图片退出后恢复当前头像，设备截图功能不受影响。
